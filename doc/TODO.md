## 维护规则

- 这里只记录尚未完成、需要持续关注的 feature。
- 每项必须包含状态、重要等级、收益程度、预计时间、改动量和可验证的验收条件。
- 开始开发时将状态改为「进行中」；完成并验证后，从本文件移除并写入 `archive/` 对应阶段记录。
- 设计细节写入 `design/`，本文件只保留目标、范围和验收条件。
- 优先级顺序：P0 阻塞项 → P1 高需求 → P2 体验增强 → Backlog 按需。

### 评估口径

| 维度 | 分级 | 说明 |
|---|---|---|
| 重要等级 | P0 / P1 / P2 | P0 阻塞发布或基础能力；P1 核心产品能力；P2 体验、质量或增强能力 |
| 收益程度 | 高 / 中 / 低 | 对核心使用频率、可用性、可靠性和用户体验的综合收益 |

## P1 · 核心产品体验

### Agent 工作台式 FE 重构

- **状态**：待开始
- **重要等级**：P1
- **收益程度**：高
- **预计时间**：1–2 周
- **改动量**：大
- **用户感受**：当前页面缺少设计感，视觉与信息层级不清晰，注意力很难集中在正在解决的问题上。
- **产品方向**：参考 Codex、Cursor Agent 一类界面，将主页面重构为专注当前问题的 Agent 工作台，而不是功能入口的堆叠。
- **需求**：
  - 以当前问题、对话和任务结果作为主视觉中心。
  - 将计划、执行步骤、工具调用和状态收敛为清晰的辅助区域，默认不抢占主内容。
  - 建立统一的字体、间距、色彩、组件状态和响应式布局规范。
  - 保留文字输入、语音、历史会话和设置能力，但降低非当前任务信息的视觉噪音。
  - 桌面端优先，同时保证移动端核心对话与任务流程可用。
- **验收**：
  - 用户进入首页后能立即识别当前问题、输入区、Agent 输出和执行状态。
  - 从提问到查看结果的主流程无需在多个页面之间切换。
  - Plan、Tool、Subagent 等过程信息层级清晰，可展开查看、可收起隐藏。
  - 建立可复用的基础组件与视觉规范，不再依赖页面级临时样式拼接。
  - 对桌面和移动端完成视觉走查，并通过现有 lint、typecheck 与 UI build。

### 复杂任务 Plan Mode

- **状态**：待开始
- **重要等级**：P1
- **收益程度**：高
- **预计时间**：2–3 周
- **改动量**：特大
- **用户感受**：面对困难任务时，当前过程不够清晰；希望像主流 Agent 产品一样，先列 Todo，再一项一项完成。
- **产品方向**：Agent 判断任务复杂度；复杂任务先创建内部执行计划，之后以 Todo 状态机驱动执行，而不是直接给出一次性答案。
- **需求**：
  - 定义简单任务与复杂任务的判定规则，并允许用户主动要求进入 Plan Mode。
  - 执行前生成可编辑的 Todo 列表，包含步骤、顺序、依赖和验收目标。
  - Todo 支持 `pending`、`in_progress`、`completed`、`blocked`、`cancelled` 状态，同时最多只有一项 `in_progress`。
  - Agent 每完成一步立即更新内部 Todo，再开始下一步；发现新工作时可追加或调整计划并说明原因。
  - 遇到缺少信息、危险操作或无法继续时，将对应项标为 `blocked` 并向用户请求输入或确认。
  - 将计划和实时进度同步到 FE；默认展示摘要，用户可展开查看详细步骤。
  - 计划与任务状态持久化，刷新页面或服务重启后可恢复。
- **验收**：
  - 给定一个多步骤任务，Agent 在执行前先展示计划，不会直接跳到最终答案。
  - 执行期间 Todo 状态按顺序变化，任何时刻都能看出当前项、已完成项和阻塞原因。
  - 用户可以修改、取消或重新排序尚未执行的步骤，Agent 按新计划继续。
  - 页面刷新或服务重启后，计划、当前步骤和执行结果仍可查询。
  - 最终回复明确汇总完成项、未完成项和验证结果。

### 主线与细节分层的 Agent 执行视图

- **状态**：待开始
- **重要等级**：P1
- **收益程度**：高
- **预计时间**：1–2 周
- **改动量**：大
- **用户感受**：希望像 Cursor 一样，主线只关注当前问题和最终调用结果；Subagent、Tool Call 等执行细节集中到可展开区域，不打断人和 Agent 的主线。
- **产品方向**：建立“主线摘要 + 细节抽屉”的双层信息模型。主线展示用户问题、Agent 当前结论、关键进展和最终结果；细节区域承载完整执行轨迹。
- **需求**：
  - 主线只展示必要的高层事件，例如“正在研究”“已完成文件修改”“等待用户确认”和最终结果。
  - `subagent`、`tool call`、参数摘要、返回结果、错误、耗时和中间步骤进入独立的执行详情区域。
  - 详情区域支持展开、收起、按步骤查看，并默认保持收起，避免大量日志淹没对话。
  - 主线和详情使用统一的任务/步骤 ID 关联，展开详情时能定位到对应的主线进展。
  - 对高风险操作、阻塞、失败和需要用户输入的事件，在主线保留清晰提示，不能只隐藏在详情区域。
  - 适配 Plan Mode：主线显示当前 Todo 项和结果，详情显示该项内部的 subagent/tool 执行过程。
  - 页面刷新或任务恢复后，主线摘要和细节轨迹仍保持一致。
- **验收**：
  - 普通用户只看主线即可理解 Agent 做了什么、当前到哪一步以及最终结果。
  - 开发者或高级用户展开详情后，可以追踪 subagent、tool call、参数摘要、结果和错误。
  - 细节数量增加时，主线布局和可读性不被破坏。
  - 失败或需要确认的执行不会被折叠隐藏，用户能从主线直接采取下一步行动。
